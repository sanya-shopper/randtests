ENT (Walker)

The ten-second answer. John Walker's ENT reads any file and prints five numbers. It cannot certify randomness — it exists to catch the gross failures before you spend compute on the real suites [Walker 2008].

What ENT computes

StatisticIdeal for random bytesWhat a deviation means
Entropy8.000 bits/byte The file is compressible — some byte values dominate
Chi-square (byte frequencies, 255 df) p-value not near 0 or 1 Symbol-frequency bias; ENT reports how often true randomness would exceed the observed χ² — outside 5–95% is suspect, outside 1–99% nearly conclusive
Arithmetic mean127.5 Global bias toward high or low byte values
Monte-Carlo π≈ 3.14159 Byte-pairs, read as 2-D points, don't fill the square evenly
Serial correlation≈ 0 Each byte predicts its successor — first-order dependence

Why it's only a smoke test

ENT's statistics see byte frequencies and lag-1 correlation, nothing else. Any structure living in pairs-of-pairs, bit planes, long-range correlations, or lattice geometry — that is, essentially every defect the real suites exist to catch — is invisible to it. A counter run through even a mediocre mixing function scores perfectly. The legitimate uses are quick triage: is this "random" file actually text? Did the hardware source get stuck? Is this data already compressed or encrypted? For those questions five numbers in ten seconds is exactly the right tool, which is why the little utility from the 1990s is still packaged everywhere; current source is maintained on Fourmilab's GitHub [Walker 2008].
