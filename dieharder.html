Dieharder (Brown, ~2003–)

Diehard, reborn as maintainable open source. Robert G. Brown of Duke University rebuilt Marsaglia's battery under the GPL, made every sample size a command-line parameter, wired it to the GNU Scientific Library, and changed the philosophy of the verdict: don't hand the user a p-value to squint at — repeat the test until a weak generator fails unambiguously.

History and design

Brown (with contributions from Dirk Eddelbuettel and David Bauer) wrote Dieharder as a "clean-room" reimplementation, named in tribute to Marsaglia. Diehard's Fortran-derived C was showing its age: fixed input files, fixed sample counts, no way to test a generator directly. Dieharder links against GSL, so it can test any of GSL's dozens of built-in generators by name, or consume raw binary from a file or stdin — which is what makes it the convenient harness for testing anything that can emit bytes, including hash functions run in counter mode [Brown et al.].

What it contains

Three layers [Brown et al.]:

LayerContents
Diehard reimplementations The full Diehard battery — birthday spacings, OPERM5, the three matrix-rank tests, bitstream, OPSO/OQSO/DNA, both count-the-1s tests, parking lot, minimum distance, 3-D spheres, squeeze, sums, runs, craps — with adjustable sample counts.
NIST STS ports The STS monobit, runs, and serial tests.
RGB & contributed tests Bit-distribution tests, a generalized minimum-distance test (Fischler's d-dimensional extension), a non-overlapping permutations test built to replace the buggy OPERM5, lagged sums, a Kolmogorov–Smirnov validation test, and David Bauer's DAB set (byte distribution, DCT, fill-tree, monobit2).

The p-value-of-p-values approach

Dieharder's defining habit is aggressive two-level testing. Each test is run many times (100 by default), and the batch of p-values is tested for uniformity with a Kuiper/KS statistic, producing a single second-level p-value reported as PASSED, WEAK, or FAILED. The point, in Brown's phrase, is to push weak generators to unambiguous failure: a marginal defect that yields an ambiguous p ≈ 0.03 in one run yields a vanishing second-level p-value once a hundred runs are aggregated — and the user can simply raise the repeat count until the ambiguity dissolves [Brown et al.].

Known issues

Dieharder's own documentation is refreshingly blunt about which of its tests to trust [Brown et al.]: OPERM5 remains suspect (the covariance bug inherited from Diehard); the overlapping-sums test "produces systematically non-flat p-value distributions and should not be used"; and several monkey-test reference statistics are asymptotic approximations that drift when the sample count is turned far up — a general hazard of second-level testing noted on the foundations page. Community assessments add that some ported reference distributions were never rigorously re-derived, so WEAK verdicts on specific tests deserve suspicion of the test, not just the generator. Overall sensitivity sits well below BigCrush and PractRand.

Where it fits

Dieharder's contribution is operational, not statistical: it made serious testing a one-liner (dieharder -a -g 201), packaged in every Linux distribution, with clear verdicts. As a research instrument it has been superseded — the modern convention for vetting a new generator is BigCrush plus PractRand — but as the accessible first battery, and as scaffolding for piping arbitrary byte streams into a broad test collection, it remains the standard utility. Version 3.31.1 is effectively final; maintenance continues in community forks.
